# 启发式对手

`game/heuristic_ai.py` 依赖 NumPy。项目 AI 网页和数据生成器使用同一个 `HeuristicAI`；历史桌面 GUI 中的独立启发式见 [GUI 说明](GUI.md)。

## 选点过程

1. 全盘枚举横、竖和两条斜线上的六格窗口，优先完成本回合剩余子数内能成六的组合。
2. 全盘检查对手可用两子补齐的窗口，计算当前回合能覆盖全部直接威胁的封堵组合。
3. 普通布局先取单点评分最高的 12 个位置，枚举双子；再模拟第一颗落下后的局面，为每个首选点补充最多 3 个搭档。
4. 模拟对手回应：普通局面取最多 6 个候选点；有直接威胁时，应手必须覆盖全部威胁，剩余子从候选中选择。按回应后的窗口价值及保留的进攻结构评分。
5. 搜索自己的连续威胁胜法；没有找到证明时，检查评分靠前的方案是否会让对手连续强制获胜。只有证明对手能赢，才尝试其他方案，最多检查 4 个。
6. 按选定双子计划依次落子。第二颗绑定第一颗落子后的精确棋盘；悔棋或其他落子改变棋盘后不会误用旧计划。

窗口里已有对方棋子时，该窗口的进攻价值为零；有空缺的连线也参与评分。直接成六优先，能够形成对手两子无法全部封堵的威胁时给予高分，但先检查对手是否能立即反杀。

## 搜索预算与证明

这不是 MCTS。普通选点是限制候选的浅层双子搜索，连续威胁搜索只延伸能迫使对手防守的进攻路线。

默认最多延伸 3 个进攻回合，每次证明搜索最多检查 384 个局面；自己的进攻证明和对手检查共用一次选点约 1 秒的截止时间。达到预算时返回“未证明”。静态候选评估与函数调度有额外开销，整次调用可能略超出 1 秒；缓存命中会更快返回。

只有在枚举的全部合法防守之后仍能获胜，才记录证明成功。对方只需一颗封堵时，其自由的第二颗也需要考虑；防守组合超过 64 个时返回未知。候选、分支、深度与预算有限，未找到胜法不等于没有胜法，未查到对手胜法也不等于局面安全。

各版本实战存在克制关系，增加搜索或候选数量不保证整体棋力提升。

## 数据生成

`noise_prob` 默认 0.1，用于预训练数据多样性。随机探索只在没有本方即时胜法和对手直接威胁时发生。网页版和评测设为 0，候选同分排序固定；计时截止和缓存仍可能影响后续搜索发现的路线。

## 检查

```sh
python -X utf8 -B -m unittest discover -s tests -p "test_heuristic*.py" -v
```

检查覆盖两子补空获胜、直接威胁封堵、黑白双方斜线、连续威胁证明、对手反杀、第二颗计划执行、候选补充和搜索预算。连续威胁回归局面还独立枚举全部合法防守，核对证明结果。
